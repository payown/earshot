# Earshot SwiftUI — Phase 1 Planner Review

Reviewed on branch `fix/issue-425-freeze-schema-v3-migration` (2 commits ahead of `swift`). Scope: the 7 core feature areas plus cross-cutting concurrency, accessibility, and error handling.

## Overall health

The SwiftUI rewrite is in good shape. The architecture is clean and consistent: pure rules (`PlaybackLogic`, `ChapterParser`, `SleepTimerLogic`, `QueueLogic`, `FeedRefreshPolicy`) are factored out of side-effecting services so they unit-test without AVFoundation or a network, and the test suite is genuinely substantial (441 test methods across 44 files). Error handling is mature for a v1: nearly every `try` is wrapped, failures are logged through `AppLog` with `privacy: .public` redaction, and the migration-loading dead-end lesson from the Flutter side is respected (DB-touching launch work is guarded). Accessibility is a clear first-class concern throughout — custom rotor actions, hand-authored scrubber semantics, stable button names with live `accessibilityValue`, single-point play-state announcements, and `minTouchTarget` framing are applied deliberately and mostly correctly.

The real gaps are functional, not structural. The most important is that **chapter auto-skip silently does nothing unless the user has opened the player-controls sheet** (the only place that feeds the chapter list to the engine). The feed parser is **RSS-only with a single rigid date format**, so Atom feeds and feeds using named time zones lose publish dates or fail entirely. There is no Podcast Index search (iTunes only), no transcript surface despite the data being parsed, and chapter images are parsed but never shown. On concurrency: the project is still Swift 5 with `SWIFT_STRICT_CONCURRENCY: minimal`, so the Swift 6 migration is real but not yet started; the code is largely `@MainActor`-disciplined, which is the right foundation, but there are a handful of spots (the volume-fade `DispatchQueue` chain, `@Model` capture across `Task` hops) that will need attention when strict mode is turned on. None of the findings are crashes against well-formed data; the P1 items are functional correctness and one accessibility-completeness gap.

## Feature area findings

### 1. Audio playback (AVPlayer engine, queue, rate, restoration)

Solid core. Single `AVPlayer`, clean separation into `PlaybackLogic` for the testable rules (resume threshold at 95%, source resolution preferring local file, speed clamping/rounding, next-up id). Restoration on launch via `PlaybackStartup.restoreLastEpisode` loads paused with saved position — correct and tested. Gapless preload (`refreshPreload`/`preloadedItem`) and auto-advance are well thought out, including reusing the prepared item only when it still matches the next id. Position persistence is deliberately throttled (#362) with eager saves on the durability anchors (pause/seek/switch), and now-playing elapsed time is throttled (#412) with discontinuity re-anchoring — both good engineering with pure, tested cadence functions.

Issues: P1-1 (auto-skip dead unless controls sheet opened) is the headline. P1-4 (fade race) and P1-5 (skip interval not pushed to remote) are real. P2-5 (duration write not promptly saved), P2-8 (no observer teardown), P2-11 (stale last-episode after advance-on-empty-queue). Interruption and route-change handling (`oldDeviceUnavailable` pause, `.shouldResume` resume) is correct and matches PRD 5.5.

### 2. Feed parsing (RSS, refresh)

`XMLParser`-based, covers RSS plus `itunes:` and `podcast:` namespaces (chapters, transcript). The refresh logic is the strongest part of this area: high-water-mark seeding, future-date poisoning guard (#296), backfill path for migrated shells, auto-queue enrollment, and per-feed failure isolation in `refreshAll` are all carefully handled and tested. `ParsedFeed`/`ParsedEpisode` are `Sendable`, which sets up the off-actor parse cleanly.

Gaps: P1-2 (no Atom), P1-3 (single date format) are the correctness risks for real-world feeds. P2-1 (no Podcast Index), P2-2 (transcripts dropped), P3-1 (GUID fallback) follow. The parser does not process namespaces (qualified names), which is fine and intentional but means a feed using a non-standard `itunes` prefix wouldn't match — acceptable edge.

### 3. Per-podcast settings

`PodcastSettingsView` binds directly to the `Podcast` `@Model` with `@Bindable`, immediate persistence, no save button — clean. Optional-to-concrete binding bridges for speed/queue-age/inbox-max/inbox-age/notification are correct. Notification permission requested idempotently on first enable. Headers carry `.isHeader`. The one real issue is P2-10 (per-row `accessibilityLabel` inside Picker likely ignored by VoiceOver). Otherwise complete and matches the model fields frozen in V3.

### 4. Bookmarks

`BookmarkRepository` is minimal and correct (add with clamped position + trimmed note, list sorted by position, delete, guarded save). `BookmarksListView` is a strong accessibility example: combined row element with jump activation, custom rotor actions for share/delete, visible share button hidden from VoiceOver to avoid a duplicate stop, swipe actions, `@State` reload after mutation to avoid stale focus. Only gap is P3-3 (no note editing after creation).

### 5. Sleep timer

Clean split: `SleepTimerController` (`@MainActor @Observable`) drives state and a 1s `Timer`; `SleepTimerLogic` holds pure math and the spoken/clock formatting (including the coarse `spokenRemaining` so a focused VoiceOver cursor isn't re-spoken every tick — a nice detail). End-of-episode mode handled in both the timer and `handlePlaybackEnded`. Cancels on play-something-else with a guarded announcement. Only P3-6 (verify resume-from-suspension re-checks expiry) is worth a glance; the `endDate` math makes it low risk.

### 6. Lock screen / Now Playing (MPNowPlayingInfoCenter, MPRemoteCommandCenter)

Good coverage: title/artist/duration/elapsed/rate set, artwork fetched through the shared disk-backed `ArtworkCache` (survives relaunch, #378/#385), artwork write preserves other fields, elapsed-time throttle with discontinuity re-anchor. Remote commands wired for play/pause/toggle/skip-fwd/skip-back/changePlaybackPosition, all `[weak self]` with `.commandFailed` fallback. The one defect is P1-5 (skip intervals fixed at launch). No `MPRemoteCommandCenter` previous/next-track commands are wired — minor, since skip is the podcast idiom, but worth a future note.

### 7. Background refresh (BGTaskScheduler)

`BackgroundFeedRefresher` is careful: stable identifier matching Info.plist, re-schedule-before-work chain, throttle window via `FeedRefreshPolicy`, expiration honored via `isCancelled` threaded into `refreshAll`, and all DB work in do/catch so it can't become a dead end. Per-podcast new-episode notifications delivered with a swallow-on-failure notifier. The only concern is P2-9 (the whole refresh, including network, runs on `@MainActor`), which matters mainly for the 100+ feed tester under a tight BGTask budget.

## Cross-cutting concerns

### Swift 6 concurrency

The project is **Swift 5 / `SWIFT_STRICT_CONCURRENCY: minimal`** (project.yml:14-15); a `feature/swift6-strict-concurrency` branch exists but the reviewed line is unmigrated (P2-7). The foundation is right — services that touch `ModelContext.mainContext` are uniformly `@MainActor` (`PlayerService`, `QueueRepository`, `SubscriptionRepository`, `DownloadManager`, `BookmarkRepository`, `SubscriptionImporter` is a `@ModelActor`), pure logic types are stateless enums, and DTOs (`ParsedFeed`, `ParsedEpisode`) and `ArtworkCache` are explicitly `Sendable`. The migration risks are concentrated: `@Model` (`Episode`/`Podcast`) instances are not `Sendable` yet are captured by `self` and read inside `Task { @MainActor in ... }` closures fired from AVFoundation/NotificationCenter callbacks (P2-6); these will warn under `complete`. Recommended path: `targeted` → fix → `complete` → language mode, converting the already-on-main callbacks to `MainActor.assumeIsolated` rather than `Task` hops.

### Accessibility

Generally exemplary and the strongest cross-cutting area. Recurring good patterns: stable button names + live `accessibilityValue` (play/pause), hand-authored scrubber via `.accessibilityRepresentation` with 30s adjust steps and a drag/adjust latch, decorative icons `accessibilityHidden(true)`, `minTouchTarget` framing on transport buttons, headers marked, single-point play-state announcement at the TabView root to avoid 5x firing across inset bars (#366), magic-tap toggle, custom rotor actions mirroring visible menus, and the `spokenRemaining` coarsening to avoid re-speaking ticking timers. Gaps are narrow: P2-10 (Picker row labels), P3-4 (silent scrubber pre-duration). Tab order in `RootView` follows visual order. No contrast/Dynamic Type red flags found in the reviewed views; `ViewThatFits` in `NowPlayingBar` specifically protects touch targets at large type sizes.

### Error handling

Mature. Nearly every `try` is `do/catch` with `AppLog` logging and `privacy: .public` redaction of user content; failures degrade rather than crash (artwork returns `nil`, downloads mark `.failed`, refresh continues past a bad feed, migration-touching launch work is guarded per `.claude/rules/database-migrations.md`). `HTTPClient` has a real retry policy (5xx + connectivity, never 4xx/parse) with injectable backoff for tests. No force-unwraps were found on the hot paths reviewed; optional model access is consistently guarded. The main "silent failure" risks are user-facing rather than crash-causing: the export-gated-on-Wi-Fi generic failure (P2-4) and dropped pubDates (P1-3) both fail quietly in ways the user can't diagnose.
