## Action decisions

Queue retains its own saved enabled/available order and the existing default:
Play now, Remove from queue, four move actions, Open show notes, Download.
The new shared Episode actions start **Available**, so existing configured,
disabled and partial saved lists do not acquire a new double-tap or rotor
action. Queue-specific Remove and Move keep their existing handlers, grouped
move boundaries and focus behavior.

| Episode action | Queue behavior |
| --- | --- |
| Play now, Download / Remove Download, Open show notes | Existing Queue IDs now use the same Episode metadata and runner. |
| Mark as Played / Unplayed | Opt-in; shared explicit Played mutation. Respects Keep finished episodes in Queue; never implicitly plays next. Focus moves only after an actual Queue removal. |
| Bookmarks, Share | Opt-in; open the same Bookmarks or link share flow. |
| Export transcript, Export audio | Opt-in; only applicable when a transcript or audio URL exists. Use existing export flows. |
| Refresh episode audio | Opt-in; only when a podcast is attached; existing recovery path. |
| Add to another folder, Move to one folder | Opt-in; open the same folder picker, including its move confirmation. |
| Unfollow this podcast | Opt-in; opens the existing destructive podcast confirmation. |
| Play next, Add to top/end of Queue | Omitted because the row is already queued; Queue Move commands express position changes. |
| Remove from Inbox | Omitted; a Queue row is not the Inbox removal surface. |

The first configured Queue action is promoted to VoiceOver double tap only
when applicable. If it is unavailable, ordinary episode details remain the
default; a later action is not promoted. Remaining configured actions keep
their rotor order. Existing touch Play, details, selection and Queue-only
pickup/drop controls remain separate. New actions use the same labels and
destructive roles as Episode rows. Queue IDs are unchanged for existing
actions; future unknown stored IDs are retained when this build saves a Queue
configuration. An older app cannot be made to understand newly added IDs.
