# Earshot 1.1.1 plan

## Objective and release boundary

Earshot 1.1.1 is a focused follow-up release for three tester-visible
improvements:

1. Continue an OPML import after the free subscription limit is reached and
   the listener buys or restores Earshot.
2. Let VoiceOver listeners choose which episode details Earshot speaks in the
   Inbox.
3. Let listeners choose how much of the show notes VoiceOver includes in an
   Inbox episode row.
4. Speak enough of a podcast's description in the Library for a listener to
   understand what the show is about, with control over verbosity.

Implementation starts from the final 1.1.0 tag after 1.1.0 is Ready for
Distribution. The 1.1.1 work must not hold up 1.1.0 unless a new release-blocking
1.1.0 defect is discovered.

Jonathan Mosen's public Mastodon feedback is the product input for these
changes: <https://caneandable.social/@JonathanMosen/116988043821870892>.
His requested 14-day trial is explicitly out of scope. Silence trimming is also
out of scope for this patch release because it requires a separate audio-DSP,
energy, and playback-quality investigation; Earshot should not expose a switch
until it has a real implementation.

These features require no new CloudKit record type or production schema
deployment.

## Track A: resumable OPML import after purchase

### Current behavior and problem

The importer parses the selected document and calls the subscription repository,
which correctly applies the free limit and reports imported, failed, and
limit-skipped counts. Importing the same file again after purchase is safe:
canonical feed URL matching avoids duplicate subscriptions and the OPML folder
structure is processed again.

The gap is continuity. When onboarding reaches the free limit, the original
document is released and there is no durable pending-import state. Buying
Earshot does not cause the skipped subscriptions to continue, and several entry
points do not connect the limit result to the paywall. A listener must know to
find and select the same OPML file again.

### Intended experience

- Every OPML entry point—onboarding, Settings > Data, Add Podcast, Share/Open
  In, and future entry points—uses one import coordinator and one result model.
- If an import reaches the free limit, Earshot stages the original OPML data
  locally before presenting the purchase path. It must copy the data while it
  has security-scoped access; it must never retain the external URL and assume
  access will remain valid.
- A verified purchase or restore initiated from that import flow automatically
  continues the staged document. Existing subscriptions are reused and the
  remaining subscriptions and folders are imported.
- If the listener cancels or dismisses the paywall, Earshot keeps the pending
  import and exposes a clearly labelled **Continue importing N podcasts** action
  in Settings > Data. Onboarding also explains that the import can be continued
  later.
- If entitlement becomes active later or on another launch, Earshot offers the
  continuation instead of silently starting an old, potentially large import.
- The listener can discard a pending import. Selecting another OPML document
  while one is pending asks whether to replace the pending document or return
  to it. Version 1.1.1 supports one pending document at a time.
- Completion or explicit discard removes the staged document. Cancellation or
  force-quit leaves a retryable pending document.
- Import progress does not move VoiceOver focus once per feed. Earshot provides
  concise progress/status and one final summary that separately reports added,
  already present, failed, and free-limit-skipped subscriptions.

### Storage and implementation design

Add a shared `@MainActor @Observable` OPML import coordinator at the application
root. It owns the import state machine and delegates parsing/subscription work;
views only present state and send user intentions. Do not put import business
logic in individual SwiftUI views.

The staged file belongs in Application Support with complete file protection,
backup exclusion, and a small atomic metadata record containing a content hash,
display name, creation date, and result counts. It is local continuation state,
not user sync data, and must not be uploaded through CloudKit. Reprocess the
whole staged document after entitlement verification instead of manufacturing
a second OPML document: repository idempotence preserves the first subscriptions
and gives the remaining entries the original folder context.

The state machine must make completion, retry, cancellation, duplicate feeds,
invalid feeds, purchase failure, restore failure, process death, and a changed
entitlement explicit. It must never infer a purchase from a dismissed paywall;
continuation begins only after `EntitlementStore` reports verified access.

### Automated tests

- Parse and stage OPML documents above the free cap; verify the staged bytes and
  metadata survive coordinator recreation.
- Import the free allowance, verify purchase, continue the same document, and
  assert each feed exists once with its folder assignment preserved.
- Cover purchase, restore, paywall dismissal, offline purchase failure,
  cancellation, relaunch, retry, discard, replacement, malformed OPML, duplicate
  outlines, and mixed valid/invalid feeds.
- Exercise 60-feed and substantially larger fixtures (at least 500 and 1,000
  feeds) and assert cancellation remains responsive and memory does not scale
  through duplicated document copies.
- Test all import entry points against the same coordinator contract.
- Keep StoreKit unit suites excluded for the known Xcode 26.6
  `SKInternalErrorDomain Code=3` runner issue (#679); verify purchase and restore
  continuation with Sandbox on a physical device.

### Physical-device acceptance test

1. Start without purchase access and import an OPML file containing more than
   ten subscriptions and nested folders.
2. Confirm the free allowance imports, the remaining count is accurate, and
   the library remains responsive with VoiceOver.
3. Buy or restore from the import flow. Confirm the import continues without
   reselecting the file and ends with one accessible summary.
4. Confirm every feed appears once and folders match the OPML file.
5. Repeat while dismissing the paywall, relaunch Earshot, use **Continue
   importing**, and confirm the same result.
6. Repeat once offline and after force-quitting during the import; verify safe,
   duplicate-free recovery.

## Track B: customizable Inbox speech

### Product choices

Add a **Spoken episode details** section to Settings > Inbox using native
SwiftUI controls. Episode title remains mandatory because removing it would
make rows indistinguishable. Now Playing state, button traits, actions, and
other interaction-critical semantics are also mandatory.

Provide these toggles in a fixed order for 1.1.1:

- Podcast name — on by default.
- Published date — on by default.
- Download or streaming status — on by default.
- Duration or time remaining — on by default.

Keep season and episode number controlled by the existing Appearance setting;
do not create a conflicting second toggle. Field reordering is not part of
1.1.1: choosing fields solves the reported verbosity problem without adding an
accessible reorder editor to a patch release.

Defaults must reproduce the current spoken Inbox label and value byte-for-byte.
Preferences are device-local so a listener can use different verbosity on an
iPhone and Mac, and a remote device cannot unexpectedly change the VoiceOver
experience. Do not add these keys to the CloudKit-mirrored setting scope.

### Implementation design

Create a small, value-type spoken-details configuration and a pure row-speech
composer. Pass it explicitly from `InboxScreen` to `EpisodeRow`. All other
`EpisodeRow` call sites keep the existing default policy so this feature cannot
silently alter Downloads, Queue, search, or another screen.

Persist the settings through the existing settings layer. The generic row must
not independently observe several settings or rebuild unrelated lists. Changes
should update Inbox speech immediately without moving VoiceOver focus or
posting an unsolicited announcement.

## Track C: show-notes speech in Inbox

### Product choices

Add a **Show-notes preview** picker beside the spoken-detail controls:

- Off — do not include a show-notes preview in the row.
- Brief — current sentence/word-bounded preview, capped at 140 characters.
- Full — the complete sanitized plain-text show notes.

Brief is the default and must preserve current behavior. Explain that Full can
make each Inbox item lengthy. The existing full Show Notes action remains
available in every mode; its paragraph navigation and accessible links remain
the best experience for structured or very long notes.

### Implementation design

Extend the pure row-speech composer with the preview mode. Sanitize markup and
omit unusable whitespace without speaking raw HTML. Full preview must be lazy
and bounded by the existing summary-cache strategy so merely displaying a
large Inbox does not parse and retain every full description. Cache by episode
identity, source-text revision/hash, and preview mode; invalidate when the show
notes change.

The setting changes only what VoiceOver speaks for the Inbox row. It does not
truncate stored show notes, change the visible row, remove links from the full
Show Notes view, or alter playback actions.

### Automated and accessibility tests for tracks B and C

- Lock the default label, value, traits, hint, actions, rotor behavior, and field
  order to the current strings.
- Cover each toggle independently and representative combinations, including
  missing podcast metadata and no empty accessibility value or dead air.
- Cover Off, Brief, and Full; exact 140-character boundary behavior; sentence
  and word boundaries; empty notes; HTML; entities; links; very long notes; and
  invalid markup.
- Prove settings persist locally and are absent from CloudKit projection keys.
- Measure scrolling, row composition, cache size, and first VoiceOver focus with
  a large Inbox and long descriptions. Full mode must not cause eager work for
  off-screen rows.
- Run the full `EpisodeRowLabel` and accessibility regression suite to prove
  Queue, Downloads, search, and other surfaces are unchanged.
- With VoiceOver on, test swipe and explore-by-touch navigation, each control in
  Settings, instant row updates without focus loss, interruption of Full speech,
  the Show Notes screen's paragraph/link navigation, large Dynamic Type, iPhone,
  and Designed for iPhone on Mac.

## Track D: podcast descriptions in Library

### Current behavior and product choices

A Library podcast row currently speaks the podcast title, author, and read-only
status. Although the Podcast model stores the publisher's description, the row
does not expose it. A VoiceOver listener who does not recognize a title must
open the podcast before learning what it is about.

Add a **Library** Settings screen with a **Podcast description** picker:

- Off — preserve the 1.1.0 row speech without a description.
- Brief — speak a sanitized, sentence/word-bounded description capped at 240
  characters.
- Full — speak the complete sanitized plain-text podcast description.

Brief is the default. That makes the reported discovery improvement available
without requiring listeners to find a setting, while Off supports fast library
browsing and Full supports people who want all available context. Explain that
Full can make each Library item lengthy. Keep this preference device-local for
the same reason as the Inbox speech preferences.

### Implementation and acceptance criteria

Create a pure `PodcastRowSpeech` composer shared by the normal and multi-select
Library row variants. Keep the existing title/author/read-only accessibility
label byte-for-byte and provide the selected description as the accessibility
value. This preserves the row's accessible name for Voice Control and keeps its
button/link traits, selected state, focus behavior, Quick Actions rotor, and
activation unchanged.

Reuse a common Off/Brief/Full preview-mode type with the Inbox show-notes
setting, but allow each surface to define its own brief limit. Sanitize and
cache podcast descriptions lazily by podcast identity, description hash, and
mode. Empty or markup-only descriptions must produce no accessibility value,
not an empty spoken pause. No off-screen row should eagerly process a full
description.

Automated tests must cover Off, Brief, and Full; the 240-character boundary;
sentence and word boundaries; empty text; HTML; entities; links; invalid markup;
very long descriptions; cache invalidation after feed refresh; normal and
multi-select rows; read-only podcasts; exact preservation of labels, traits,
selection, and rotor actions; device-local persistence; and large-library
performance. Manual VoiceOver testing must cover swipe and explore-by-touch
browsing, changing the picker without a focus jump, interrupting Full speech,
opening the podcast, entering and leaving selection mode, iPhone, and Designed
for iPhone on Mac.

## Delivery sequence

Keep each pull request below the repository's 1,500-line non-generated review
limit and assign it to `@payown`:

1. **OPML domain and durability:** pending-import model, protected staging
   storage, coordinator state machine, and unit tests.
2. **OPML presentation and purchase continuation:** route every entry point
   through the coordinator, add pending/continue/discard UI, and integrate
   verified purchase/restore.
3. **Spoken-content preference model:** device-local Inbox and Library settings,
   native Settings controls, shared preview modes, pure speech composers, and
   exhaustive string tests.
4. **Inbox row integration:** Inbox-only policy injection, Off/Brief/Full cache
   behavior, performance tests, and cross-surface accessibility regressions.
5. **Library row integration:** normal and multi-select Library policies,
   lazy podcast-description caching, performance tests, and preservation of
   labels, selection state, focus, and Quick Actions.
6. **Stabilization:** merge only after review, run the full supported test suite,
   regenerate the Xcode project only if `project.yml` changes, and perform the
   physical-device matrix below.

No track may change purchase UI, accessibility semantics outside the explicitly
approved Inbox customization, signing, entitlements, or CloudKit production
schema without separate sign-off.

## TestFlight and release gates

- 1.1.0 is publicly released and its launch, migration, CloudKit, playback
  handoff, heat, and crash telemetry are stable enough to branch 1.1.1.
- Every 1.1.1 PR passes focused tests, the full supported suite, strict Swift 6
  concurrency compilation, `git diff --check`, and accessibility review.
- Large OPML tests pass at 60, 500, and 1,000 feeds. Physical Sandbox purchase
  and restore each continue the pending import without file reselection.
- Inbox defaults sound exactly like 1.1.0. Each Inbox field choice, show-notes
  mode, and Library description mode passes VoiceOver testing on iPhone and Mac
  with no focus or responsiveness regression. Library Brief is intentionally a
  new default; Off must reproduce the 1.1.0 Library row speech exactly.
- Run upgrade tests from the App Store 1.1.0 build to the 1.1.1 candidate with
  both a small library and a library above 1,000 podcasts.
- Upload the candidate to both Internal and Public TestFlight groups with a
  Kashe chapter and explicit tests for OPML continuation, Inbox speech, and
  Library podcast descriptions.
- Hold the candidate for tester feedback and crash review. Any crash must be
  checked by build number and symbolicated signature before App Review submission.
- Submit 1.1.1 only after the OPML, VoiceOver, upgrade, offline, relaunch, and
  crash gates pass and release notes/privacy disclosures have been reviewed.
