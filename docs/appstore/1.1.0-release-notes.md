# Earshot 1.1.0 release notes

Scope: customer-visible work merged after TestFlight build 155, beginning with
build 156 and ending with the App Store candidate, build 205. Build 155 itself
is deliberately excluded. The comparison boundary is commit `00482a0` through
`0c1392d`.

## Recommended App Store “What’s New” copy

Earshot 1.1 is a major update built around private iCloud sync, better library
organization, and a smoother experience with large podcast collections.

- Keep followed podcasts, folders, queue order, playback positions, played
  state, bookmarks, listening history, and shared settings synchronized through
  your private iCloud account. Downloads and purchase access remain on each
  device.
- Organize podcasts and individual episodes in nested folders. Browse new
  episodes, downloads, listening statistics, and grouped queues by folder, use
  batch actions, preserve folder structure in OPML exports, and choose a folder
  while following a show.
- Automatically download episodes added to the queue, optionally delete
  downloads after they are played, or clear all downloads in one step. Newly
  followed podcasts now avoid downloading recent episodes until you choose to
  queue or download them.
- Import large OPML libraries while Earshot and VoiceOver remain responsive.
  Library upgrades, repeated launches, feed refresh, and iCloud reconciliation
  are also faster and safer for large collections.
- Find the Now Playing controls more easily with VoiceOver Explore by Touch,
  and switch a podcast’s episode order with one reversible Oldest/Newest sort
  control that never starts playback.
- Refresh the Library on demand, load older episodes in manageable pages, and
  see honest iCloud and refresh status without routine announcements taking
  focus.

This update also reduces unnecessary work and heat during accelerated playback,
improves Bluetooth playback-rate information, and includes many VoiceOver,
sync, reset, queue, refresh, and migration reliability fixes.

## Detailed release scope

### Private iCloud sync

- Added private CloudKit synchronization for followed podcasts, folder
  hierarchy and membership, queue order, playback position and played state,
  bookmarks, listening history, and shared settings.
- Kept downloaded audio, download preferences, and purchase access
  device-local.
- Added an iCloud Sync settings screen with active status, an honest
  last-completed value, account continuity protection, and one-time
  announcements for persistent failures.
- Added distinct controls for clearing one device and deleting the synchronized
  library everywhere.
- Made offline changes durable across restart and able to reconcile after the
  connection returns.
- Hardened conflicting edits, folder-cycle repair, duplicate prevention,
  tombstones, remote unfollow, and deletion of an episode currently displayed
  or playing.
- Updated an open Now Playing screen when a newer saved position arrives from
  another device.

### Folders throughout the app

- Added nested podcast folders with accessible breadcrumbs, expand/collapse,
  reorder, and go-up navigation.
- Added podcast and individual-episode folder membership, multi-select batch
  filing, and clear Add versus Move actions.
- Added folder-scoped Inbox, Downloads, Recently Expired, and Listening Stats
  views.
- Added Queue grouping by folder and a “Playing from” path that returns to the
  originating folder.
- Added touch context menus matching configured VoiceOver rotor actions.
- Preserved nested folders in OPML export and offered folder placement while
  following a podcast.

### Downloads and library management

- Added automatic downloading for queued episodes, enabled by default while
  still respecting the Wi-Fi-only preference.
- Added an optional Delete Downloads After Played setting.
- Added Clear All Downloads with confirmation and cancellation of active
  downloads.
- Changed newly followed podcasts to download no recent episodes by default,
  preventing surprise network, storage, and processing use after a large
  import. Deliberately queued episodes can still download automatically.
- Added a Library refresh control with accurate success, partial-success, and
  failure reporting.
- Added bounded older-episode paging instead of loading an entire long-running
  catalog at once.

### Performance, migration, and reliability

- Made large OPML imports responsive by parsing and fetching away from the
  interface, batching persistence, avoiding repeated identity lookups, and
  preventing duplicate subscriptions.
- Moved database migration and preparation away from the launch watchdog path,
  added recoverable safety backups and storage guidance, and hardened
  interrupted migration and reset recovery.
- Fixed the build-202 large-library upgrade watchdog and build-203 repeated
  launch delay by replacing broad relationship faults and repeated whole-library
  fetches with bounded scalar and membership lookups.
- Bounded whole-library feed refresh work, made refresh results reflect durable
  saves, stopped foreground-owned refresh work after device lock, and preserved
  real iOS background tasks.
- Reduced continuous and accelerated-playback housekeeping so playback speed no
  longer multiplies periodic background work.
- Published both current transport rate and selected playback speed to
  Bluetooth accessories.

### VoiceOver and interaction improvements

- Made the mini player discoverable with Explore by Touch above the tab bar,
  including the native persistent tab accessory on iOS 26.
- Kept VoiceOver responsive and focus stable during migration, large OPML
  imports, folder browsing, sync rebuilding, and older-episode paging.
- Kept routine iCloud synchronization quiet while exposing useful status on
  demand.
- Replaced the podcast episode-order action with one Oldest/Newest toggle that
  only sorts and never starts playback.
- Ensured remote deletion safely closes affected episode and Now Playing
  screens, stops removed playback, and returns the user to a usable interface.

## Intentionally omitted from public copy

- Build numbers, internal schema names, migration version numbers, test counts,
  and the build-202/build-203 incident history are implementation and review
  details rather than customer-facing release notes.
- Removing an individual episode from Inbox remains device-local in 1.1 because
  each device constructs Inbox from its local episode catalog. This is a known
  limitation, not a newly advertised feature.
- Features already present in build 155 are not repeated here even when later
  builds changed their implementation or added regression coverage.
