# Build 312 physical retest and paired queue isolation

Michael repeated the watch-open steps after updating to Earshot 1.2.6 (312). The iPhone crashed again at 23:57:20 Pacific on 2026-11-06. The report is from an iPhone 17 Pro Max on iOS 27.2 (24B5084k), and its app UUID `0D00D9EC-22A8-3A5E-946E-9FA32091FC1D` matches the build 312 archive and exported IPA. The termination is again `CODESIGNING Code 2, Invalid Page`. The matching dSYM resolves the fault to `PairedQueueContribution.isValid` from `CloudProjectionCoordinator.pairedQueueContributions`, called by the phone's `queueSnapshot` reply. The first build 312 repair did **not** resolve the crash. The private report is outside the repository.

The common trigger is immediate paired queue snapshot exchange. The underlying reason iOS rejects this executable page is still unknown. A fresh compile and distribution signature did not solve it, so build 313 isolates the entire immediate snapshot path on both devices. A phone running 313 rejects snapshot requests from an older watch before reaching the validator; a watch running 313 does the same for an older phone. Neither device initiates a new snapshot or queue-change invalidation. The persisted paired overlay file is left untouched and ignored while the transport is isolated. No SwiftData store, CloudKit record, user queue entry, entitlement, or signing setting is deleted or migrated.

CloudKit's existing per-device queue contributions and offline outboxes continue to provide durable queue synchronization and conflict handling. They may arrive later than the immediate paired channel did. Manual Refresh Queue reports this limitation rather than claiming success. Playback state, direct phone/watch controls, independent watch playback, downloads, and episode/position/rate handoff continue over their existing channels. Handoff no longer waits for a paired queue snapshot, so the next queue episode may arrive through CloudKit after the transfer. This is a temporary, explicit limitation until the immediate transport can be rebuilt and physically verified.

## Physical acceptance

Update in place to build 313 on iPhone and watch; do not delete app data. Open the watch app repeatedly with Earshot foregrounded and backgrounded on iPhone. The iPhone must remain running. Verify the watch can still control iPhone playback and transfer the current episode in both directions. Confirm the manual queue refresh announces that immediate paired refresh is unavailable, while local queues remain usable. Check that queue changes eventually reconcile through iCloud when both devices have internet access, without promising a fixed delay. If a crash recurs, capture its exact time and build number and compare its stack with the matching build 313 dSYM before claiming this isolation worked.
